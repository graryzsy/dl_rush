# DL Rush

部署在飞牛 fnOS Docker 中的下载流量调度工具，带中文网页控制台。

**能产生真实下载流量，但不保存下载文件。** 容器向你提供的 HTTP/HTTPS 地址发起 GET 请求，分块接收响应体，每块最多 64 KiB，计数后立即丢弃。也可以使用在服务端动态产生数据的接口，这样两端都不需要事先准备实际文件。完全不接收网络数据则无法产生真实下载流量。

## 已实现

- 持续运行，或按“运行 N 秒 → 暂停 M 秒”循环。
- 每日运行时段，支持跨午夜；所有定时与每日统计统一采用北京时间 UTC+8。
- 下载限速，单位 Mbps；每日响应体流量上限，单位 GiB。0 表示不限制。
- 实时速度、近 60 秒曲线、今日与累计流量、最近运行事件。
- 最多 20 个下载源，单任务、单连接依次轮换；连接失败时退避重试。
- 管理员密码、同源写操作校验、容器健康检查、非 root 运行。
- 配置和统计持久化；已启用的任务会在容器重启后继续调度，关闭网页不影响任务。

## 在飞牛 OS 部署

1. 将整个项目文件夹放进飞牛的 Docker 项目目录。`Dockerfile`、`compose.yaml`、`app.py`、`web/` 必须保留在同一项目下。
2. 复制 `.env.example` 为 `.env`，将 `ADMIN_PASSWORD` 改成至少 12 位的独立密码。示例密码不能直接使用。`WEB_PORT` 默认为 `8787`，端口被占用时可修改。
3. 在飞牛 Docker 的 Compose/项目功能中选择这个项目目录进行构建和启动；也可通过 SSH 在项目目录执行：

   ```bash
   docker compose up -d --build
   ```

4. 打开 `http://飞牛的局域网IP:8787`。浏览器会提示输入用户名和密码：用户名为 `admin`，密码为 `.env` 中的 `ADMIN_PASSWORD`。
5. 填写允许使用的下载源，保存设置，然后点击“启动任务”。首次部署不会自动产生下载流量。

例如 `.env`：

```dotenv
ADMIN_PASSWORD=这里替换成你自己的长密码
WEB_PORT=8787
```

如果飞牛的编辑器只接受 Compose 内容而不能上传项目目录，请先把代码放到 NAS，再在 SSH 中运行上述构建命令；本项目没有发布可直接拉取的预构建镜像。使用 `python:3.12-slim` 作为基础镜像，不需要安装 pip 或 npm 依赖，也不要求特权模式、host 网络或映射 Docker socket。基础镜像提供 amd64/arm64 版本；构建会选择宿主机平台，本次验证平台见下文。

若已有 NAS 反向代理，可以代理到该端口并启用 HTTPS。当前网页登录使用 HTTP Basic；直接 HTTP 连接适用于可信局域网，跨互联网访问应通过 HTTPS 或 VPN。

## 设置示例

每日 01:00–07:00 内，每次接收 60 秒、暂停 120 秒，限速 20 Mbps，每日最多接收 10 GiB：

| 设置项 | 填写值 |
| --- | --- |
| 下载源 | 你自己的数据流接口或允许使用的测速地址 |
| 运行方式 | 间歇运行 |
| 每次运行 | 60 秒 |
| 间隔暂停 | 120 秒 |
| 每日定时 | 开启，01:00 至 07:00 |
| 下载限速 | 20 Mbps |
| 每日流量上限 | 10 GiB |

持续模式在允许时段内持续接收；一个响应结束后至少等待 1 秒再发起下一个请求。间歇周期从启用、修改设置或进入允许时段时重新开始。停止任务后将结束当前连接；网络调用的连接/读取超时为 5 秒。达到每日上限后等待北京时间次日 00:00，再结合运行时段决定何时继续。

20 Mbps 约等于 2.5 MB/s，全天持续运行约产生 216 GB（约 201 GiB）响应体流量。间歇、每日时段和流量上限可组合使用。

## 数据与统计

- 响应体不写入文件，也不会交给浏览器接收。没有下载目录、下载缓存或下载临时文件。
- 命名数据卷 `dl-rush-data` 只保存 `/data/config.json` 与 `/data/stats.json`。设置在变更时保存，统计约每 15 秒及控制操作、正常退出时写入。突然断电时最近约 15 秒的统计可能丢失。
- 内存中仅保留有限的数据块、近 60 秒流量桶、最近 60 条事件。容器日志有轮转限制。
- 限速与额度以程序读取的响应体字节为准。HTTP/TLS/TCP 头、内核接收缓冲以及关闭连接时丢弃的未读数据也会消耗网络流量，所以路由器/运营商计量通常更高；每日上限不是网卡层的硬上限。
- 多个下载源顺序轮换；发生网络错误会以 2、4、8…最多 60 秒的间隔重试，避免无间隔请求。TLS 证书验证保持开启。
- 请填写你有权持续使用的接口。项目不预置第三方流量源。地址中的查询参数可能包含令牌，因此配置文件按私密数据处理，不公开展示到日志。
- 新容器挂载同一数据卷即可恢复设置与累计统计；删除命名卷会清空这些数据。启用状态也会恢复，若不希望重启后继续运行，请先在页面停止任务。

## 本地运行与验证

Python 3.12 或更新版本，无第三方运行依赖：

```bash
export ADMIN_PASSWORD='自行替换成至少12位的密码'
export DATA_DIR='./data'
python3 app.py
```

测试仅连接本机生成的数据流，不请求外部测速站点：

```bash
python3 -m unittest discover -s tests -v
```

浏览器自动化测试使用 Playwright，属于开发验证工具，不包含在运行镜像中：

```bash
python3 tests/browser_smoke.py
```

构建镜像后，还可以测试实际 Compose 容器。该测试会创建临时项目和命名卷，并在结束时清理它们：

```bash
docker build -t dl-rush:local .
python3 tests/docker_smoke.py
```

本次已在 Linux/amd64 环境通过 11 项后端测试、Chromium 桌面/手机网页测试，以及实际 Compose 容器的接收、额度停止、数据卷内容、健康检查和重启恢复测试。尚未连接你的飞牛设备进行实机部署，arm64 平台也未在本次环境中运行验证。

## 常见问题

**网页显示运行中，速度很低或为零？** 检查地址是否能返回响应体、是否需要登录、是否被限速。很小的页面可以产生少量流量，但不适合持续下载测试；建议使用自己的较大数据流接口。下载源完成后有 1 秒重连间隔。

**能只“伪造下载”而不接收数据吗？** 不能。如果需要让 NAS 网卡、路由器或运营商真实记录下载字节，必须有数据经过对应链路。程序做到的是接收后直接丢弃，不保留实际文件。

**会写硬盘吗？** 下载内容不会落盘；设置、流量计数和有上限的 Docker 运行日志仍会写盘。系统启用 swap 时，操作系统也可能换出进程内存，本工具不控制宿主机的内存换页策略。

**能用内网地址测试吗？** 可以，但只有数据实际经过的链路会产生相应流量。内网源不会为互联网宽带产生下载流量。

**是否已经部署到我的飞牛？** 没有。本项目提供代码与 Compose 配置，需要放到你的 NAS 上启动。
